# Topview 涨粉变现工作流设计规格

## 架构

浏览器中的 React 操作台只负责交互与可视化；Express API 负责业务规则、Schema、文件上传、持久化、导出和备份；`data/projects/<id>/project.json` 是项目事实源。配置保存在 `config/`，Skill 的参考资料与脚本复用同一口径。

## 数据流

用户向导或库页面提交数据 → API 校验 → 业务服务生成评分/脚本/制作包/诊断 → 项目聚合 Schema 再校验 → 临时文件落盘并原子替换 → 仪表盘重新聚合。浏览器刷新后从 API 恢复，不依赖 localStorage 业务数据。

## 页面

统一侧栏和顶部栏承载 12 个入口；首页按 KPI、十步工作流、增长趋势/漏斗、选题评分、人工/自动任务、最佳视频组织。其余页面提供真实表单、生成、筛选、勾选、导出或数据录入操作，不创建无行为按钮。

## 数据与错误处理

项目 ID 使用 `^[a-z0-9][a-z0-9-]{2,63}$`；文件名只保留安全字符且使用唯一前缀；上传限制 10 MiB；恢复包拒绝绝对路径与 `..`。零分母指标返回 `null`，界面显示“暂无数据”。错误统一返回请求 ID 与中文消息，日志不含凭据。

## 测试

单元测试验证公式、评分、诊断、路径安全和迁移；集成测试覆盖 CRUD、刷新恢复、上传、各类生成、人工任务、发布/数据、导出、备份恢复和错误 JSON；Playwright 覆盖 1920/1600/1440/1366 宽度、导航、向导、菜单折叠、刷新和截图。

## 商业边界

工具本地交付状态为 READY，可作为内容代制作、模板包和咨询交付底座；商业验证状态仍为 BUILDING。演示经营数字均明确标记，不用作市场或收入证据。
