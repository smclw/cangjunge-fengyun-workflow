# “待手动操作”面板内部滚动设计规格

## 目标

避免“待手动操作”中的长任务列表撑高首页，让该卡片与旁边的“AI自动完成”卡片保持接近的视觉高度，同时保留全部任务及勾选能力。

## 设计

- 仅为首页 `.manual-panel` 内的任务列表设置约 `301px` 的最大高度和纵向滚动，默认完整显示前 9 项，不影响其他页面使用的 `.check-list`。
- 列表右侧增加约 `5px` 的细滚动条；轨道弱化，滑块使用蓝青色并带圆角，滑块位置表示当前浏览进度。
- 为滚动条留出右侧内边距，避免遮挡任务文字；滚动停留在卡片内部，不带动外层页面。
- 卡片标题、待办数量、装饰、任务顺序、完成状态和勾选保存逻辑保持不变。
- 桌面、平板和移动端均使用内部滚动，防止长列表再次撑高首页。

## 实现范围

- 修改 `app/client/src/styles/theme.css` 中与 `.manual-panel .check-list` 直接相关的样式。
- 如端到端测试缺少滚动容器断言，则补充首页测试，确认任务列表可滚动且任务勾选功能不受影响。
- 重新生成最终界面截图。

## 验收

- 长任务列表的 `scrollHeight` 大于 `clientHeight`，且 `overflow-y` 为 `auto`。
- 滚动前完整显示前 9 项，第 10 项及后续内容通过卡片内部滚动查看。
- 首页不再由待办数量无限向下拉长；滚动条清晰但不抢视觉焦点。
- 类型检查、生产构建和 Chrome E2E 通过。
- Git 提交不得包含当前项目数据或用户说明书文件的变化。
