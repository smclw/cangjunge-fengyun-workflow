# 故障排查

## 双击启动没有打开页面

查看 `data/logs/startup.log`、`server.log` 和 `server-error.log`。确认 `node.exe --version` 是 22.x，`npm.cmd --version` 可用。再运行：

```powershell
powershell.exe -ExecutionPolicy Bypass -File scripts\validate.ps1
```

## 4173 被占用

启动脚本会尝试 4173—4199。实际地址记录在 `.runtime/server.json` 和启动日志中，不要假设永远是 4173。

## 提示已在运行

这是重复启动保护。脚本会打开已有地址。若服务确实异常，先双击 `停止工作流.bat`；不要用任务管理器批量结束所有 Node 进程。

## 页面空白或 API 报错

先按 Ctrl+F5。然后执行 `npm.cmd run build` 并重启。项目 JSON 若损坏会自动尝试同目录 `project.json.bak`；无法恢复的项目会被列表隔离并在直接访问时返回错误，不会拖垮其他项目。

## 上传失败

检查 10 MiB 上限、扩展名、真实 MIME 和基础文件签名。Office 新格式必须是有效 ZIP 容器；HTML、SVG、脚本和可执行文件不允许上传。

## 数据更新冲突

同一项目在两个页面同时编辑时，旧 revision 会收到 409。刷新页面确认最新数据后再保存，避免无提示覆盖。

## 恢复失败

系统只接受含有效 `data/projects/<安全ID>/project.json` 的备份。ZIP 路径穿越、文件过多、展开超过 100 MiB、JSON 无效或 Schema 不匹配都会被拒绝。
